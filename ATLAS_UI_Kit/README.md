# ATLAS UI Kit

Учебная библиотека компонентов для Help Desk. Сохранены исходная семантическая разметка и подписи; значения цветов вынесены из правил компонентов в токены. Система поддерживает системную, светлую и тёмную темы, обычную и компактную плотность.

## Запуск

Из этой папки выполните:

```bash
python -m http.server 5500
```

Откройте <http://localhost:5500>. В проекте нет сторонних UI-библиотек и зависимостей сборки.

## Архитектура токенов

1. **Примитивы** (`--base-*`, `--space-*`, `--font-*`) задают палитру и шкалы без привязки к конкретному элементу.
2. **Семантические роли** (`--color-*`) описывают назначение значения: основное действие, поверхность, текст, граница или статус.
3. **Токены компонентов** (`--button-*`, `--control-*`, `--alert-*`, `--component-gap`) подключают роли и размеры к конкретным компонентам. Правила компонентов не содержат HEX-цветов.

Реальные цепочки:

| Primitive          | Semantic             | Component                 | Использование          |
| ------------------ | -------------------- | ------------------------- | ---------------------- |
| `--base-blue-700`  | `--color-primary`    | `--button-bg-primary`     | Фон основной кнопки    |
| `--base-white`     | `--color-on-primary` | `--button-text-primary`   | Текст основной кнопки  |
| `--base-slate-950` | `--color-text`       | `--button-text-secondary` | Текст вторичной кнопки |

Тёмная палитра переопределяет только семантические роли: системная применяется при `prefers-color-scheme: dark`, а ручная — через `data-theme="dark"`. Режим `auto` удаляет атрибут темы. Компактная плотность меняет размеры и интервалы компонентными токенами, не копируя их CSS.

Настройки темы и плотности независимо сохраняются под ключами `atlas-theme` и `atlas-density`. Если `localStorage` недоступен, переключатели продолжают работать до перезагрузки страницы.

## Проверки

| Условие                                            | Ожидаемый результат                                                     |
| -------------------------------------------------- | ----------------------------------------------------------------------- |
| Ширина 320, 375, 768, 1024 и 1440 px               | Нет горизонтального переполнения; содержимое и уведомления читаемы      |
| Переключение «Системная / Светлая / Тёмная»        | `auto` следует системной теме; ручной выбор имеет приоритет             |
| Перезагрузка после выбора темы                     | Выбор восстанавливается независимо от системной темы                    |
| Переключение «Обычная / Компактная» и перезагрузка | Плотность меняется и сохраняется отдельно от темы                       |
| Tab и Shift+Tab                                    | Все кнопки и списки доступны с клавиатуры, фокус виден                  |
| Hover, active и disabled у кнопок                  | Состояния визуально различимы; disabled-кнопка не активируется          |
| Ошибочное поле email                               | Есть контрастная граница и связанное через `aria-describedby` пояснение |
| Четыре типа уведомлений в обеих темах              | Статус понятен по символу и тексту, а не только по цвету                |
| `prefers-reduced-motion: reduce`                   | Плавная прокрутка отключается, переходы сокращены                       |

## Проектные решения

**Почему плотность задаётся компонентными токенами?** Высоты контролов, горизонтальные отступы и интервалы — свойства геометрии компонентов, а не цвета или семантического назначения. Переопределение одного набора компонентных переменных сохраняет единый CSS и не смешивает плотность с темой.

**Почему тёмная тема не задаёт цвета прямо в `.button`?** Компонент должен выражать назначение через токен, чтобы ручная и системная темы могли менять палитру централизованно. Это предотвращает расхождение вариантов кнопок и упрощает проверку контраста.
